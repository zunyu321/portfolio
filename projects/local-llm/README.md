# 本地大模型部署与离线问答

在只有集显的机器上把大模型跑起来，做成一个能回答本地资料、并且全程离线的问答助手。

## 结构

```
本地文档 ──切分──> 片段库 ──检索──> 上下文 ──> 本地模型 ──> 回答
                                        ↑
                                  OpenAI 兼容接口（/v1/chat/completions）
```

上层应用不关心模型在哪，只认 OpenAI 兼容的接口地址，换一行配置就能从云端切到本地。

## 走的几条路

- **推理后端**：llama.cpp 系（Ollama 封装），CPU 也能跑，显存不够时自动退回内存
- **模型选型**：优先能稳定跑完一轮的规模，再往上加；先要「跑得动」，再要「答得好」
- **量化档位**：从低到高逐档试，记录每档的每秒 token 数与回答质量，取折中点
- **检索**：本地文档切块后做向量化，命中片段拼进上下文，缓解模型对未见过资料的胡编
- **服务化**：用 OpenAI 兼容接口包一层，前端 / Agent 工具统一按标准协议调用

## 参数上踩的坑

- 上下文开太大直接把显存吃满，改为按模型规模给上限，长文档靠检索而不是靠塞
- 并发一高就排队，索性限制单并发，保证首字延迟可控
- 温度、top_p 对小模型影响比对大模型明显，试出来一套稳定的默认值

## 效果与取舍

- 全程离线，数据不出本机，可断网使用
- 回答准确性受模型规模限制，靠检索补，不靠堆参数
- 不是所有任务都值得本地跑：需要强推理的场景仍然交给云端模型
