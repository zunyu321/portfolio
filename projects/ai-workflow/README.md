# AI-Native 开发工作流

把 AI 编码工具当主力开发手段，跑通「需求 → 实现 → 验收 → 交付」的闭环。这里记录的是可复用的部分：拆分方式、验收标准、提示词与技能模板。

## 一套跑顺的流程

1. **先写清楚要什么**：目标、输入输出、验收标准，一条一条列出来，别让模型替你想需求
2. **拆到能验收的粒度**：一次只交一个模块，做完立刻跑，不通过就不往下走
3. **自己负责串联**：模块之间的接口、状态、打包由人串，不整段甩给模型
4. **卡住先缩小**：日志 + 最小复现，把问题压到能一句话描述，再问
5. **沉淀**：跑通的提示词、技能模板、检查脚本存下来，下次直接复用

## 沉淀的东西

- `AGENTS.md`：项目约定，模型先读这个再动手
- Skills / 提示词模板：按任务类型分开，如「加一个面板」「补一个测试」
- PowerShell 脚本 + Windows 计划任务：把重启、导出、定时抓取这类重复操作交给机器
- 验收清单：功能、异常路径、打包产物各跑一遍，关键逻辑补最小测试用例

## 踩过的坑

- 整段投喂需求，产出能跑但返工多，后来改成先拆再交
- 让模型一次改多个文件，回滚困难，改成小步提交
- 验收只靠肉眼，漏掉边界情况，补了脚本和用例后稳定很多
